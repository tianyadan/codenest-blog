# 2026 年 8 月计划：Java 深耕、Python 提效、AI 落地

这是我给自己定的 8 月方向。不是什么高大上的路线图，就是把最近纠结的几件事想清楚：该不该广学 Python、Java 要深到哪、大模型到底是啥、以及在 Mac 上能玩到什么程度。

---

## 第一部分：职业方向与策略

### 问 1：Java 后端 1-2 年、月薪 8k，该深耕 Java 还是广学 Python？

**答：**必须「7 分精力深耕 Java，3 分精力学 Python」。

前 1-2 年是打地基的关键期。你的核心竞争力——面试定薪、解决线上问题——几乎 100% 来自 Java 底层：JVM、并发、MySQL。Python 更像瑞士军刀，用来提效，别本末倒置。

再说一句扎心的：AI 时代，「会写代码」不值钱，「会审代码、能发现 AI 写出来的隐患」才值钱。后者靠的就是你对 Java 底层的理解深度。

### 问 2：Java 要深到什么程度才能涨薪？具体学什么？

按对薪资影响的权重排：

**1）高并发编程（JUC）——权重最大，大概 40%**

目标：啃透 `ConcurrentHashMap`、`ThreadPoolExecutor`、AQS 源码。

面试常考：线程池 7 大参数怎么配？锁升级过程？`CompletableFuture` 怎么做并行？

**2）JVM 调优 —— 次之，大概 35%**

目标：能用 `jstack`、`jmap`、Arthas 排查线上 OOM 和 CPU 飙升。

面试常考：CMS 和 G1 区别？内存溢出时怎么定位到哪行代码？

**3）微服务治理 —— 再往后，大概 25%**

目标：搞明白服务发现、熔断降级，能画出自己项目的架构图。不用钻太深，大多数公司都是用现成方案。

阅读建议：别贪多。只看两本书的核心章节——《Java 并发编程实战》前 5 章，以及《深入理解 Java 虚拟机》第 2–5 章。

### 问 3：什么时候可以学 Python？

现在就可以，但得「功利」一点学。

每天大概花 30 分钟，只学能直接帮到 Java 工作的 4 个库：

- `requests`：发 HTTP 请求
- `pandas`：清洗 Excel / 日志
- `openpyxl`：写报表
- `smtplib`：自动发邮件

原则很简单：先别碰 Python 的 Web 框架（Flask / Django），也别去啃并发底层（asyncio）。那不是现在该花时间的地方。

## 第二部分：大模型的技术底层

### 问 4：大模型本质是什么？是代码还是权重文件？

本质是**权重文件（Weights）**。

就是一个装着几十亿个浮点数（比如 `0.231`、`-0.567`……）的巨大文件。这些数字是模型的「记忆」和「知识」，靠训练堆出来的。Python 代码更像搬运工，权重才是灵魂。

推理过程说白了：输入文字，跟这些权重做一堆矩阵乘法，最后预测下一个词。

### 问 5：这些权重数字是怎么算出来的？

靠「反向传播」（Backpropagation）。大致三步：

1. **前向传播（猜答案）**：问「中国的首都是？」模型按当前权重瞎猜个「上海」。
2. **算损失（看差距）**：正确答案是「北京」，算出差了多少。
3. **反向传播 + 参数更新（记教训）**：把损失往回传，给每个权重算个梯度，再微调一遍数字，让下次猜得准一点。

这个过程得在成千上万张 GPU 上，对着海量数据迭代不知道多少轮。贵，而且慢。

### 问 6：企业是不是一直堆显卡、加参数，就能无限变强？

以前差不多是这样，现在不是了。「堆显卡、加参数」已经撞上边际效益递减这堵墙。

原因很现实：

1. 砸万亿参数的钱（动辄数亿美元），换来的性能提升越来越小。
2. 算力太贵，企业扛不住。

所以业界现在主要走两条路：一是系统级优化，让成千上万张卡真正协同起来；二是架构创新，比如 MoE（混合专家），在不显著增加计算量的前提下，把有效参数做大。

### 问 7：MoE 和蒸馏（Distillation）是一回事吗？

不是一回事，但可以组合用。

| 维度 | MoE（混合专家） | 蒸馏（Distillation） |
|------|----------------|----------------------|
| 优化对象 | 模型结构 | 模型知识 |
| 核心机制 | 模型里有多个「专家」+ 一个「路由器」；提问时只唤醒 2–3 个相关专家 | 用大模型（教师）生成数据，训练小模型（学生），把能力「压」进去 |
| 降本原理 | 减少每次推理的计算量（稀疏激活） | 减少模型参数量（轻量化） |
| 类比 | 微服务改造，按需调用 | 师徒制，大牛带新人 |

企业常见做法：先蒸馏出一个靠谱的小模型，再把它做成 MoE 架构，把成本往死里压。

## 第三部分：落地实操

### 问 8：Mac 24GB 内存，能自己微调一个 2B 模型吗？

完全可以，而且挺轻松。

24GB 微调 2B 绰绰有余。就算玩 8B–14B，只要用 QLoRA（4-bit 量化）或 LoRA 这类参数高效微调，内存一般也能压在 10GB 以内。

推荐工具：

- **MLX**：苹果官方框架，对 Mac 优化最好，速度也快。
- **LLaMA-Factory**：社区里很火的「一键式」微调工具，支持 LoRA / QLoRA。

### 问 9：微调能把模型调成什么样？能变成「企业专家」吗？

能，但得分层看：

| 层次 | 你的需求 | 效果 | 怎么做 |
|------|----------|------|--------|
| 第一层（最佳） | 改说话语气、设角色（客服、技术专家） | 很擅长 | 准备 100–500 条对话样本就行 |
| 第二层（良好） | 注入企业规章、产品手册这类固定知识 | 比较擅长 | 需要 500–2000 条高质量 QA |
| 第三层（瓶颈） | 培养复杂推理分析能力 | 效果有限 | 最好配合 RAG，先查资料再回答 |

别指望微调一把梭，就把模型变成全能专家。

### 问 10：让 AI 掌握企业信息，微调好还是 RAG 好？

强烈建议优先 RAG（外部知识库 + 向量检索）。微调不适合用来「记企业信息」。

| 维度 | 微调 | RAG（推荐） |
|------|------|-------------|
| 知识更新 | 极慢，得重新训练 | 改文档就能生效 |
| 会不会编造 | 严重，容易胡编 | 可控，可以引用原文 |
| 能不能答新信息 | 不能，卡在训练截止日 | 能，立刻检索新文档 |

真实企业玩法是组合拳：

- **RAG 负责「知识」**：文档、制度、产品信息，实时更新。
- **微调负责「人格」**：学会像客服那样说话、按固定格式出报告。
